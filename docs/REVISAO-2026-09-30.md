## Resultado e uso

Caddy continua como proxy central (equivalente ao papel do NGINX). As rotas públicas ficam em `config/caddy/Caddyfile`. Porta e interface ficam no `.env`: `ACCESS_PORT=8443`, `ACCESS_BIND=0.0.0.0`. Não é necessário domínio, certificado ou editar o hosts do Windows. Os endereços internos Docker continuam sendo nomes dos serviços; não substitua por IPs do servidor.

Grafana: http://172.16.27.51:8443/
Cadastro: http://172.16.27.51:8443/monitoramento/

Para acessar via IP público, encaminhe a porta TCP externa no firewall para a porta 8443 do SRV-DUNKER. Isso depende de IP público roteável, NAT e liberação do firewall; os arquivos não configuram esses equipamentos. HTTP transmite credenciais sem criptografia. Prefira VPN para acesso externo até habilitar HTTPS.

Login do cadastro: admin e senha do arquivo `config/secrets/grafana_admin_password`. O cadastro tem autenticação própria, sem compartilhar a sessão Grafana. Se a senha foi alterada dentro do Grafana, essa alteração não modifica o arquivo usado pelo cadastro.

## Instalar a atualização no Windows

1. Faça backup da pasta atual e dos volumes Docker. Não use `down -v`.
2. Extraia o ZIP de atualização sobre a raiz do projeto existente. Ele não contém `.env`, senhas nem inventário e não deve substituir esses dados.
3. Na pasta do projeto, execute:

```powershell
docker compose -f compose.separado.yaml config --quiet
docker compose -f compose.separado.yaml up -d --build
docker compose -f compose.separado.yaml ps
docker compose -f compose.separado.yaml logs --tail=80 admin ping caddy grafana
```

Se já utiliza o modo único, use `compose.unico.yaml` nos comandos. Não execute os dois modos juntos: disputam as portas. Mantenha o mesmo nome de projeto e os volumes existentes. Na atualização, a imagem local deve ser reconstruída com `--build`.

A porta 8443 foi preservada para reduzir alterações no ambiente. Para usar 80, acrescente `ACCESS_PORT=80` ao `.env` e recrie o serviço proxy. Prometheus e Alertmanager permanecem acessíveis apenas no loopback do servidor. Syslog 1514 é um protocolo separado; seu bind continua configurável em `SYSLOG_BIND`.

## Cadastro e coleta

O botão “Cadastrar IPs / Pings” nos dashboards abre a tela no mesmo endereço. É integração por link, não um plugin nativo ou formulário embutido no Grafana.

Cadastre nome, cliente, unidade, provedor, IPv4 local ou público, frequência, timeout por pacote, quantidade e intervalo dos pacotes, limites de perda/latência e criticidade. A tela permite editar, pausar, excluir e testar com os mesmos parâmetros multipacote. A criticidade é uma etiqueta informativa; não muda automaticamente o peso do cliente.

O inventário canônico é `config/targets/inventory.json`; Blackbox usa `config/targets/icmp.json`, gerado pelo cadastro. Na primeira execução, um inventário vazio é migrado de `config/inventory.json`. Uma marca evita repovoar o cadastro depois de excluir todos os monitores. O arquivo antigo permanece como fonte de migração; não continue editando os dois inventários.

O ping carrega mudanças sem reiniciar. Até 32 medições são executadas em paralelo, sem sobrepor rodadas do mesmo monitor. Se uma rodada dura mais que a frequência ou faltam trabalhadores, a próxima aguarda. Uma rodada com N pacotes pode durar aproximadamente N × max(timeout, intervalo). A perda tem resolução de 100/N por cento: 5 pacotes produzem passos de 20%.

O Blackbox continua verificando disponibilidade a cada 15s com timeout de seu módulo (5s), independentemente da frequência multipacote. Assim há duas medições com propósitos distintos. Os campos da tela controlam o ping multipacote, usado para perda e latência; não controlam a coleta rápida Blackbox.

Limites personalizados agora são usados nas regras de latência e perda. Persistência de alerta: 5 minutos; disponibilidade sem resposta: 2 minutos. Dashboards e regras são provisionados; mudanças nos dashboards locais podem ser substituídas no reinício conforme a configuração de provisionamento.

Importação CSV é uma operação manual de substituição do inventário inteiro. O início dos containers não importa CSV automaticamente, evitando apagar o cadastro visual. Pare o serviço admin enquanto importa CSV e reinicie em seguida para evitar gravações concorrentes. Exporte ou faça backup do inventário antes dessa operação.

## Achados de revisão

- Admin existia, mas não era iniciado em nenhum modo; agora ambos iniciam e roteiam a tela.
- Ping lia inventário vazio em pasta diferente do importador; agora ambos usam a mesma fonte.
- Scripts exigiam HTTPS e aguardavam certificado mesmo com proxy HTTP; isso foi corrigido, incluindo geração de agentes.
- Frequência era adicionada ao tempo de duração da rodada e um alvo lento bloqueava os demais; agendamento foi separado por monitor.
- Limites personalizados eram ignorados pelas regras; agora participam das comparações e da tolerância de dados antigos.
- Segredos constam no histórico Git do ZIP enviado. `.gitignore` foi corrigido, mas não remove o histórico. Guarde credenciais no 1Password, retire os arquivos rastreados com `git rm --cached -r config/secrets` e `git rm --cached ACESSOS-PRIVADOS.txt` se ainda rastreado, e considere rotação conforme quem teve acesso ao repositório. Preserve `grafana_secret_key` enquanto o banco atual depender dela.
- Não removi SNMP, Alloy, Loki, Alertmanager nem dashboards: são usados para firewalls, servidores e logs. Alertmanager atual não possui destino de notificação configurado; alertas existem, mas não enviam mensagens automaticamente.
- O PDF e resultados de validação antigos descrevem a versão anterior; não são evidência desta atualização. Este documento e o LEIA-ME são as instruções atuais.

## Validação e limites

Validados: compilação Python, sintaxe shell, parsing dos YAML/JSON, fluxo HTTP de autenticação, cadastro, edição, pausa, exclusão e leitura pelo exporter. Verificado parsing de resposta ICMP e geração de métricas.

Este ambiente não possui Docker, Caddy ou promtool. Não houve construção de imagens, validação executável de PromQL/Caddy ou teste dos containers. ICMP real foi bloqueado pelas permissões deste ambiente; a prova de coleta precisa ser feita no SRV-DUNKER com NET_RAW (configurado nos dois coletores). Não há evidência de validação visual do navegador nesta sessão.

Após subir, teste um IP conhecido pela tela, consulte `dnk_ping_packets_received`, `dnk_ping_loss_percent` e `dnk_ping_config_interval_seconds` no Explore do Grafana. Confira em Prometheus `/rules` se as regras carregaram e `/targets` se os exporters estão UP. Um IP que bloqueia ICMP não comprova falha total do link.
